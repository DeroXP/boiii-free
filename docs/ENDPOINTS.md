# Outbound endpoints

Every host the inherited client can contact, from the code on `xerces-main`
(upstream `beta` f8f7b735 plus `mod-stack`), 2026-11-04. M0 item 4 in DESIGN.md;
the decisions are D9, D14 and D15 (DESIGN.md 0.2 and 16.8).
`tools/ci/check_hosts.py` fails when code adds a host that is not listed in
`tools/ci/hosts.json`.

D14 and D15 are build switches (`src/client/xerces/switches.hpp`), off by
default: `premake5 ninja --with-ezz-social` or `--with-upstream-downloaders`
builds the upstream behaviour back in.

Joining a server with a missing Workshop item opens its page in the Steam client
when you agree (`steam://url/CommunityFilePage/<id>`), so Steam downloads it.

Addresses never appear in Xerces logs (DESIGN.md 15.1). The backend's own host
joins this list in M5, the relay in M6.

A host whose lobby is open to direct connect (DESIGN.md 11.10) asks its own
router to forward the game's UDP port (UPnP through Windows' NAT API,
`upnp.cpp`) and removes the mapping when the lobby closes or the game quits.
That traffic stays on the local network and names no host.

The network password check (DESIGN.md 11.10) is messages between the joiner and
the host it joins, on the game's own UDP port; nothing else is contacted.
